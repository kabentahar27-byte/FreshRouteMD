# Usability session guide — prepared, not run

Recruit 3–5 volunteers with varied comfort using websites; include at least one Spanish speaker if possible. Obtain consent for note taking. Do not collect names in the results sheet, record health/financial circumstances, ask for documents, or imply that volunteers must disclose hardship. Use a clean browser profile or clear the hypothetical plan afterward. These are proposed sessions; no testers or results are claimed.

## Consistent hypothetical task

“Using the ingredients, equipment, and budget in this scenario, choose a meal, identify missing groceries, calculate spending, and find a potentially useful food resource.”

Scenario: A fictional person has one banana and drinking water. They have a stove, pot, spoon, fork, measuring cups and oven mitts. For this test they have no dietary/allergy selections and no refrigerator. Their hypothetical budget is $8. They want one serving. They can buy a package of old-fashioned rolled oats whose label says it contains enough oats for the recipe; the hypothetical package costs $3.25. Search near Owings Mills, save a sourced resource, and identify what must be checked before a visit. **The $3.25 is a usability scenario value entered by the tester, not a real retailer price. Do not ship it in production defaults.**

Ask the tester to think aloud. Give only the task initially; avoid telling them which controls to press. If live data fails, record that failure instead of supplying fabricated results. The food-discovery part remains incomplete until real source results load.

Record exact task steps completed, assistance given, whether they knew ingredient quantities were unconfirmed, whether they distinguished recipe cups from purchase packages, and whether they thought a saved pantry meant oats were available. Note whether “remaining” was correctly understood when a price was blank. Do not infer impact or extrapolate 3–5 observations to all Maryland residents.

Finish by asking: “What did you expect to happen that did not happen?” and “What would you need to confirm before following this plan?”

## Spanish task

“Con los ingredientes, el equipo y el presupuesto de este ejemplo, elige una comida, identifica las compras que faltan, calcula el gasto y busca un recurso alimentario que podría ser útil.”

Use the same hypothetical values and translate the scenario faithfully. Do not request the tester’s real allergies or finances. Record language problems without silently explaining away confusing interface text.

## Follow-through

Prioritize changes that caused incorrect decisions, then failures to complete, then hesitation. Record the change, code reference and a repeat observation after fixing it. No user-feedback changes have been made in this run because no real feedback has been provided.
